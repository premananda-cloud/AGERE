# 2026-08-01 — Stage 3 Push, Session 1

**Purpose of this file:** full record of today's session for picking back

## Goal for this push

Move the hover/stabilize model from Stage 2 (reached 2026-07-31) to
Stage 3, per `docs/hover-model-plan.md` §4. Stage 3 requires, verbatim:

1. Stage 2 criteria hold across **at least 3 different random seeds**
   (rules out "got lucky once")
2. Mean position error at episode end **< 0.1 m**
3. Recovers from a **mid-episode external disturbance** within a few
   seconds

**Seed clarification settled today:** "different random seeds" +
"rules out got lucky once" means *training* seeds, not eval-sample
seeds — train the policy from scratch 3+ times with different seeds and
confirm each independently-trained policy clears Stage 2 (and ideally
0.1 m). Resampling eval episodes against one existing policy doesn't
address this.

## Session narrative, in order

### 1. Plan doc written
Created `docs/stage3-push-plan.md`, laying out the four-step approach:
diagnose the existing tail → cheap fixes → multi-seed retrain →
disturbance-recovery eval.

### 2. Baseline re-evaluated with new instrumentation
The 07-31 Stage 2 run reported mean position error 0.088 m with 2/20 tail
episodes at 0.24–0.29 m, but nothing about *why* — `evaluate.py` didn't
log start conditions, `gym_wrapper.py`'s `reset()` didn't expose them.

**Instrumented:** `reset()` now returns `start_position`/`start_yaw_rad`
in its info dict. `evaluate.py` gained `--seed` (seeds only the first
reset; gymnasium's RNG then carries forward deterministically, making the
whole 20-episode sequence reproducible for rerun/comparison), plus
per-episode start-jitter and yaw-jitter logging.

**Result of `python -m src.training.evaluate --seed 42`** (same model as
the 07-31 run, different but now-reproducible eval sample):
- Mean final position error: **0.099 m** — right at the Stage 3 bar
- Crash rate: 0%
- **4/20 tail episodes** (>0.2 m): episodes 10, 13, 15, 18

**Notable finding independent of the tail's cause:** the mean flipped
from comfortably-under-0.1 m (0.088 m) to right-at-the-boundary
(0.099 m) just from a different eval sample of the *same* policy — "mean
< 0.1 m" wasn't yet a stable property of that model.

### 3. Tail diagnosis — start condition ruled out
Added jitter-magnitude and yaw-jitter correlation against final position
error.
- Position jitter vs. final error: **+0.27** (ambiguous by the numbers,
  and confirmed not real on inspection — episode 2 had the largest jitter
  in the set, 0.407 m, but one of the smallest errors, 0.028 m)
- Yaw jitter vs. final error: **+0.07** (no relationship)

**Conclusion:** tail not explained by start condition.

### 4. Tail diagnosis — trajectory shape
Added per-step position-error tracking, classifying each tail episode as
"converged then drifted" vs. "never converged."

**Result: all 4 tagged "never converged,"** with varying shapes —
episode 18's best value was at the very last step (still closing the gap,
ran out of episode); episode 15 plateaued at step 42/240 and made no
further progress for the remaining ~200 steps (more concerning shape);
episodes 10/13 peaked mid-to-late and ended slightly worse than their own
best.

**Conclusion:** genuine convergence-speed/completeness issue. Two
candidate explanations left open: undertraining vs. a reward-shape
problem (`hover-model-plan.md` §5's note that smoothness/survival terms
could compete with the position term).

### 5. Training seed support added
`train.py` and `ppo_policy.py` had no seed parameter — added `--seed`,
passed through to SB3's `PPO(..., seed=...)`. Saved filenames are now
seed-aware (`hover_stabilize_ppo_seed{N}.zip}`).

**Also found:** `device="cpu"` was already set in `ppo_policy.py` —
`status.md` incorrectly said this was outstanding. Corrected in
`status.md` this session; no code change was needed.

### 6. First retrain — seed 0, 500k timesteps
Ran `python -m src.training.train --seed 0 --timesteps 500000` (up from
the original 200,000) to test whether the tail was undertraining. Full
config/results in `training-log.md` run `2026-08-01-0`; summary:

- `ep_rew_mean`: -87.5 → -14.3 over training, steady climb, no
  instability signs (`approx_kl`, `clip_fraction` stayed in normal
  ranges throughout; `std` dipped up to ~1.11 mid-run then settled to
  0.849)
- **Eval (`--model hover_stabilize_ppo_seed0.zip --seed 42`, same 20
  start conditions as step 2/3 above): mean position error 0.025 m, 0/20
  tail episodes.** Tail problem resolved — confirms undertraining, not
  reward shape, was the original cause.
- **But: crash rate 5% (1/20).** Episode 14, `truncation_reason: tilt`,
  final pos error 0.152 m. First crash seen in any eval run of this
  project. Start condition unremarkable (jitter 0.234 m, yaw 8.4°, both
  mid-distribution) — same "not start-condition-driven" pattern as the
  earlier tail.

### 7. `evaluate.py` bugfixes (found because of the seed-0 crash)
Two problems surfaced once a real crash showed up in the data:
- The tail report only triggers on position error, so a crash with a
  final error under the tail threshold (episode 14's 0.152 m < the 0.2 m
  default) went completely unreported. **Fixed:** added a dedicated crash
  report, independent of `--tail-threshold`, that always fires for any
  crashed episode and includes `truncation_reason`.
- The closing "neither start condition predicts the tail" paragraph was
  printing even when `tail_idx` was empty (i.e., using stale correlation
  numbers from before the tail-episode loop). **Fixed:** gated the whole
  correlation/description block on `tail_idx` being non-empty.

### 8. Second retrain — seed 2, same settings
`python -m src.training.train --seed 2 --timesteps 500000`. Full details
in `training-log.md` run `2026-08-01-1`; summary:
- `std` at convergence: 0.684 (tighter than seed 0's 0.849)
- **Eval (`--seed 42`): mean position error 0.018 m — best result of any
  run this project has produced. Crash rate 0% — the seed-0 tilt crash
  did not reproduce.** 0/20 tail episodes.
